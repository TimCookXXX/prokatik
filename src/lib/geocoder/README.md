# Свой геокодер: поиск адреса (`src/lib/geocoder`)

Чистый TypeScript без БД и сети. На вход — `GeoIndexData` (контракт `types.ts`, данные — OSM + ГАР, собранные
конвейером исходного проекта sravniprokat и загруженные `pnpm geo:import`), индекс живёт в памяти процесса.
Внешних сервисов нет. Движок перенесён из sravniprokat без изменения поведения; почему свой геокодер и как он
встроен в сервис — [ADR 0021](../../../docs/decisions/0021-own-geocoder-and-listing-coordinates.md).

```ts
import { createGeocoder, buildClientIndex, createClientGeocoder } from "@/lib/geocoder";
const g = createGeocoder(data);                       // ~0,4 с на 460 тыс. домов
g.suggest("базовкая 21 корп 1 яблоновский", { near }); // подсказки «Где», сразу с координатами
g.geocode("г. Краснодар, ул. Ставропольская, 106", { near }); // пакетная привязка: один однозначный ответ или null
g.geocodeDetailed("Садовая 5", { near });             // то же + причина отказа: { hit: null, reason: "ambiguous_place", message: "…уточните пункт", alternatives }
g.reverse(45.0404, 38.9767);                          // «Моё местоположение»: дом ≤ 60 м, иначе улица, иначе пункт

// мини-индекс для браузера: улицы, пункты, объекты без домов (≈ 250 КБ gzip)
const json = buildClientIndex(data);                  // сервер, раз на версию данных
createClientGeocoder(json).suggest("базов", { near }); // браузер: тот же движок, мгновенно; дома — с сервера
```

- `suggest(q, { limit = 5, near })` — до `limit` подсказок `AddressHit`. `near` — место пользователя или
  центр города (без него — крупнейший город индекса, поэтому сервер всегда передаёт центр текущего города).
- `geocode(address, { near, strict = true })` — лучший ответ, только если он уверенный и однозначный:
  - текст совпал на ≥ 0,76, лишних длинных слов нет, названный пункт не противоречит;
  - строго (по умолчанию): пункт не назван, а такой же адрес есть и в другом пункте → `null`
    («Садовая, 5» есть в Краснодаре и в Яблоновском);
  - `strict: false` — берётся ответ в пункте `near`.
- `geocodeDetailed(address, opts)` — то же, но `{ hit, reason, message, alternatives }`. Причины (`GeocodeFailure`,
  тексты — `GEOCODE_MESSAGES`):

  | reason | Когда | message |
  |---|---|---|
  | `ambiguous_place` | пункт не назван, а такой адрес есть в нескольких пунктах | «Такой адрес есть в нескольких пунктах — уточните пункт» |
  | `ambiguous` | несколько похожих адресов почти с одной оценкой | «Похожих адресов несколько — уточните адрес» |
  | `weak_match` | лучший ответ совпал меньше чем на 0,76 | «Похожего адреса нет — проверьте написание» |
  | `extra_words` | в адресе слова, которых нет ни в одном названии | «В адресе есть слова, которых нет…» |
  | `place_mismatch` | улица есть, но не в названном пункте | «Такой улицы нет в указанном пункте» |
  | `type_mismatch` | тип улицы назван, а дом найден только на улице другого типа («ул. 9-го Января, 12» → «проезд 9 Января, 12») | «Дом найден только на улице другого типа…» |
  | `not_found` / `empty` | ничего / пустая строка | «Адрес не найден» / «Пустой адрес» |

  `alternatives` — между чем выбирали (до 5, разные места): для отчёта пакетной привязки «Садовая, 5 — Яблоновский / Новая Адыгея».
- `reverse(lat, lon, { houseM = 60 })` — точка → `AddressHit`:
  - дом с настоящей точкой (здание, адресный узел) не дальше 60 м, интерполированный — 30 м → `kind: "house"`, точка дома;
  - иначе улица ближайшего дома (до 250 м) или по точке улицы (до 300 м) → `kind: "street"`, точка — переданная;
  - иначе пункт, в застройке которого точка (или ближайший до 5 км) → `kind: "place"`, точка — переданная;
  - подпись — пункт и ближайший микрорайон («Краснодар, Юбилейный»); `score` — расстояние, м; далеко от всего — `null`.
  - Сетка домов (ячейка ≈ 220 × 235 м) строится при первом вызове: 12 мс, 5 МБ; запрос — 0,04 мс.
- `AddressHit.kind` / `precision` (подробно — «Точность ответа» ниже):
  - `house` — дом есть в данных; `precision` — **ровно из данных** (`house`, `interpolated`, у домов только из ГАР
    бывает `street` или `place` — это «≈»), движок её не повышает;
  - `street` + заголовок «улица X, ≈15» — такого номера в данных нет. Точка — оценка по соседям той же чётности или
    точка улицы, но `precision` всегда `street` («≈»): это не дом. `parts.house = null`;
  - `place`, `poi`.
- `parts` — пункт, улица и номер по отдельности, для пакетной привязки и замера.

## Точность ответа: чужой или примерный дом не выдаётся как точный

Главный критерий — «до дома» (`house`, `interpolated`) только там, где дом есть в данных и его точка там настоящая.

| Что нашлось | `kind` | `precision` | Точка | На сайте |
|---|---|---|---|---|
| дом, точка здания или адресного узла | `house` | `house` | данных | без «≈» |
| дом ГАР, интерполяция **данных** | `house` | `interpolated` | данных | без «≈» |
| дом ГАР, данные пометили «≈» (соседей нет, номер комплекса, точка улицы) | `house` | `street` | данных | «≈ до улицы» |
| дом ГАР с точкой пункта | `house` | `place` | данных | «≈ населённый пункт» |
| тот же дом у двойника улицы («улица Митрофана Седина» ГАР = «улица Седина» OSM) | `house` | точность двойника | двойника | по его точности |
| номера нет в данных | `street` («улица X, ≈15», `parts.house = null`) | `street` | оценка движка по соседям той же чётности (лучше точки улицы) или точка улицы | «≈ до улицы» |

- Движок **не повышает** точность данных: дом ГАР с «≈» данных остаётся «≈», даже если соседи рядом, а номер,
  которого нет в данных, — `street`. Соседи с настоящими точками рядом влияют только на **оценку** (дом, скорее
  всего, есть там, где сказано: доверие 0,93 вместо 0,75) и на строгие отказы `geocode`, но не на `precision`.
- Строгий `geocode`: тип улицы назван, а дом найден на улице другого типа — отказ `type_mismatch` (набранной улицы
  или этого номера на ней может не быть в данных).

## Клиентский мини-индекс (`client-index.ts`)

Улицы, пункты, микрорайоны и объекты (≈ 10 тыс. записей) подсказываются в браузере без сети, дома — с сервера.

- `buildClientIndex(data, built?)` → `ClientIndex`: компактный JSON (массивы вместо объектов, координаты 5 знаков,
  словарь типов). Вместе с названиями едут посчитанные по домам величины (число домов улицы, пункт большинства её
  домов, радиус застройки пункта) — поэтому ранжирование совпадает с серверным.
- `createClientGeocoder(json).suggest(q, { near, limit })` — тот же `Engine`, та же нормализация (`text.ts`, `query.ts`),
  те же веса. Сборка — одна синхронная задача на сотни миллисекунд, на слабом телефоне — около секунды, поэтому в
  браузере её не делают в главном потоке.
- Запрос с номером («Красная 12») на клиенте даёт улицу с точкой улицы, «≈» не выдумывается; дом приходит с сервера.
- `id` клиентских подсказок начинаются с `c` и не совпадают с серверными — сверять по `kind` + `title` + `subtitle`.
- Без цифр в запросе ответ сервера совпадает с клиентским, список не прыгает. Пришёл ответ сервера — он заменяет
  клиентский список.
- **Лицензия.** Мини-индекс — выборка из производной базы OSM (дома ГАР получают точки OSM и интерполяцию по соседям
  OSM в одном слое), и его публичная раздача — распространение производной базы (ODbL 4.3–4.4). Поэтому уведомление
  едет в самом JSON (`license`, `attribution` — `CLIENT_INDEX_LICENSE`, `CLIENT_INDEX_ATTRIBUTION`). Подсказки и
  точки — Produced Work; ODbL 4.6 требует предложить получателям копию базы или способ её сборки — это страница
  «Источники данных» (`/sources`).

## Как ищем (`engine.ts`)

1. **Куски запроса** (`query.ts`, `chunkVariants`). Если в запросе есть латиница, у каждого куска три
   варианта: как набрано, раскладка (`,fpjdcrfz` → «базовская», Shift-знаки `<` → «Б», запятая в конце —
   разделитель или «б»), транслит (`ulitsa Krasnaya`, `5-y` → «5-й»).
   - Режим выбирается на весь запрос по сумме оценок словаря.
   - Кусок уходит из режима, только если другой вариант заметно лучше.
2. **Слова и номер** (`tokenize`).
   - Номер дома: «21 корп.1» = «21к1», «7-Б» = «7б», «10"А"», «21/1», «22/Б», «12 стр 2», «97 лит. Л», «88 сГ», «10Б2».
   - Выбрасываются «кв./офис/под./этаж/домофон/код/помещ./секция N», «3 подъезд», «3-й этаж», «склад», «вход со двора»
     и почтовый индекс; «д.»/«дом»/«дом номер» помечают номер. Недонабранное «Ком…», «Под…» без номера раньше — начало
     названия, а не «комната».
   - Запасные ключи номера (`houseAlts`, по порядку, если по основному дома нет): «120-5» → 120/5 → 120-5 → 120
     (дробь или дом и квартира); «22 к1» → 22/1; «113 А Краснодар» → 113а → 113; «120 в Краснодаре» → 120 → 120в
     (предлог). Буква перед «кв/офис/подъезд» — литера («113 А кв 5»), «кв.» к номеру не клеится.
   - Порядковые числа («1-й», «7я Линия», «1-е отделение», «первого») — часть названия, не дом.
   - Одиночная буква перед пунктом («58, а. Козет») — не литера. Если слитно не нашлось, есть запасной ключ без буквы.
   - Дефисы названий слитно («Кубано-Набережная» = «кубанонабережная»).
3. **Слово → словарь.** Цена совпадения (0 — точно):
   - основа (падеж: «Красной», «на Ставропольской») — 0,1;
   - фонетика («Кутузава», «Совхознае») — 0,14;
   - опечатки Дамерау–Левенштейна (1 правка от 3 букв, 2 — от 5, 3 — от 10) по словам и по основам — 0,22 / 0,42 / 0,55;
     у длинных слов — полный Дамерау (перестановка с правкой между: «дзержсикого» = 2 правки);
   - служебное слово целиком («шоссе», «ст», «край») — только точно или падежом, не опечаткой («шоссе» ≠ «Щорса»);
   - недонабранное слово в середине («Селезн 100») — начало слова, +0,1;
   - начало слова для последнего недонабранного слова, с опечаткой от 4 букв.
   - Род: «Весёлая» ≠ «Весёлый» (+0,25). После предлога «-ой» — женский род: «на Кольцевой» — улица, а не проезд.
   - Тип улицы в запросе («наб.») совпадает и со словом названия («Набережная улица»).
4. **Слова → формы названий** улиц, пунктов и POI (имя и синонимы, тип отброшен). Покрытие формы взвешено:
   - редкие слова весомее (idf);
   - титулы («Героя», «имени») — 0,3, инициалы — 0,15;
   - личное имя (`GIVEN_NAMES`: «Александра», «Евдокии», «Братьев»…) — необязательно: нет в запросе — считается 10 %
     веса («Покрышкина» = «Александра Покрышкина»); в ядре названия его нет, поэтому «Беличенко 88» при улицах
     Беличенко и Ивана Беличенко в разных пунктах строго неоднозначен;
   - у объекта необязательны все слова, кроме первого и чисел («Кубанский университет»), если совпало два слова или
     назван вид;
   - буква-сокращение рядом с совпавшим словом — слово названия («Н. Адыгея»).
   Отсекаются кандидаты, у которых совпали только числа (кроме целиком числовых улиц вроде «6-я улица»).
5. **Кандидат = улица + (названный пункт) + номер** из оставшихся чисел: с «д.» → после улицы, ближайший к ней
   («Красная 120, 44» — 120, 44 — квартира) → с буквой/корпусом → до улицы, ближайший.
   - Другие названные пункты, совместимые с местом кандидата, — не лишние слова: «г. Краснодар, п. Российский,
     ул. Пинская», «Краснодар, ЮМР, …», «Краснодар, Прикубанский округ, …» (округ — «может быть», границ нет).
     Слова региона подряд («Краснодарский край», «Динской р-н», «Республика Адыгея», «городское поселение»)
     в названия не идут; повтор использованного слова («город Краснодар, город Краснодар») — не лишнее.
   - Дом ищется в улице по ключу (и по запасным ключам, −8).
   - Не найден — «≈» (`precision: "street"`, `parts.house = null`): точка — тот же номер с другим корпусом,
     интерполяция между соседями той же чётности (только соседи с настоящими точками), сосед с одной стороны
     или точка улицы.
   - Дом из ГАР с точкой «улица/пункт»: точка того же дома у **двойника** улицы — та же улица другой записью
     («улица Митрофана Седина» ГАР = «улица Седина» OSM: тип и ядро без имён и званий совпадают, ≥2 общих
     дома ближе 150 м или у записи дома без точек), с точностью двойника; иначе — точка и точность данных («≈»).
     Один дом под двумя именами — одна подсказка.
   - Синоним улицы, совпадающий с основным названием другой улицы того же пункта ближе 3 км, — не форма
     («Сиреневая» у Инженерной рядом с настоящей Сиреневой).
6. **Оценка** — сумма, веса в `RANK`:

   | Слагаемое | Значение |
   |---|---|
   | текст | 100 × покрытие |
   | дом найден | +30 × доверие к точке (1 / 0,93 / 0,75 / 0,6; у «≈» данных с соседями той же чётности рядом — 0,93, на `precision` не влияет) |
   | «≈» | +14 × правдоподобие соседей |
   | пункт назван и подходит / не подходит | +20 / −30 (город и посёлок у его границы — 0) |
   | лишнее слово | −22 / −30 (от 5 букв) |
   | лишнее порядковое число | −25 |
   | лишнее число | −6 |
   | тип улицы совпал / нет | +4 / −6 |
   | близость пункта к `near` (от края застройки) | до +12 |
   | близость самой точки | до +8 (спад 2 км) |
   | род порядкового совпал / нет | +2 / −8 |
   | недонабранное слово не подошло | −22 |
   | «≈», когда у тёзки дом найден (только в подсказках) | −16 × (1 − правдоподобие) |
   | размер улицы | до +8 |
   | служебное слово вошло в название («имени Есенина») | +2 |
   | слово сразу после типа другого вида («ст. Калужская» у улицы, «ул. Динская» у пункта, «ЖК Янтарный» у улицы) | −25 |
   | … того же вида у пункта / объекта; тип совпал и с видом пункта («хутор Колос» — хутор, не СНТ) | +4 / +8 |
   | тип не назван, в пункте есть тёзка другого типа — у «улицы» (только подсказки) | +5 |
   | найдено без личного имени, а в том же городе есть улица ровно с таким названием («Ковалёва» ≠ «Льва Ковалёва») | −20 |
   | объект целиком: все слова его, и в названии число («ЖК Янтарный 4») или назван вид («ТЦ OZ», «Парк Краснодар»); то же у места с числом («Мега-Победа 2») | +30 |
   | почтовый индекс запроса совпал с индексом дома / другой (у дома без индекса — индекс ближайшего дома той же улицы или квартала до 300 м) | +8 / −8 |
   | назван микрорайон вместе с городом, а точка ответа не в нём (дальше 2,5 км) | −15 |
   | назван пункт, в который входит пункт-ответ («Краснодар, мкр Фестивальный», «Краснодар Калинино») | +20 × похожесть |
   | объект назван вместе с улицей своего адреса без номера («Мега на Тургеневском шоссе», «ТРЦ Красная площадь на Дзержинского») | +20 и «объект целиком» |
   | звание набрано («Атамана Кухаренко»), а у улицы его нет, при тёзке с ним | −20 |
   | у найденного дома рядом (до 1 км) названный объект («ЖК Ренессанс, ул. Строителей, 21») | +10, место названо |

   - Одноимённые улицы разных пунктов — отдельные подсказки, подпись — пункт.
   - Совпала и подпись — добавляется ближайший микрорайон или СНТ.
   - Куски одной улицы ближе 2 км склеиваются.
   - Пункт улицы для близости — пункт большинства её домов: «улица Степная» в Краснодаре, дома — в СНТ.
7. **Номер набирается** («Ставропольская 10», «Крупской 125/», «Чукотская 23 к», «Кондратенко 6 стр»):
   - `tokenize` помечает оборванный номер: `partial` = «125/», «23к», «6с» (только у последнего номера открытого запроса);
   - дом с набранным номером есть — дополнения (10А, 10/1, 100…) идут ниже него и ниже того же дома в других пунктах
     (`completionGap` = 30): «Вишнёвая 5» сначала показывает все пункты, где есть дом 5;
   - дома нет или номер оборван — дополнения встают на его место («125/1», «125/2», …), дом «125» — ниже, «≈23К» при
     настоящих «23к1», «23к2» не показывается.
8. **Набор по буквам** (последнее слово без пробела после — `prefix`):
   - начало слова: цена 0,04 + 0,3 × (недонабранная доля); если набранное уже есть в словаре целиком («Степная»),
     продолжения («Степановская») дороже на 0,1;
   - опечатка в целом слове для недонабранного дороже на 0,12: «водн» — «Водниковская», а не «Видная»;
   - недонабранное слово, которому ничего не подошло, штрафуется как лишнее (−22), даже из 1–2 букв: «1-й Мо» —
     «1-й Монтажный проезд», а не любой «1-й …»;
   - слово набирается, а в названии после него ещё слова: недонабранные засчитываются на 0,7 веса — «Никол» находит
     «Николая Кондратенко», «имени Анто» — «имени Антона Кравченко». Только при точном начале слова, не при опечатке
     («галерея» ≠ «Валерия Гассия»);
   - короткое начало (2 буквы) — до 400 слов словаря по «массе» домов, 1 буква — 150;
   - ничего не нашлось — запасной ход: опечатка уже в первых трёх буквах («Сьо» → «Со…»).
   - **Улицы и пункты выше объектов.** У кандидата считается покрытие «по набранному» (`Cand.typed`): недонабранное
     слово засчитывается долей набранных букв («же» у сокращения «женус» — 0,4, а не 0,78, как в обычном покрытии), а
     начало *составной* формы объекта — сокращения («ккб», «кубгту», «стадц») или названия слитно («озмолл»), т. е.
     одного слова, которого нет в его многословных формах (`FormRec.compound`, `index-build.ts`), — не засчитывается
     вовсе. Объект назван целиком или почти (`typedWhole`), если `typed` ≥ 0,7 или совпали два слова названия и
     больше («красная площадь», «оз м», «мега ад»). Иначе при наборе он ниже на `RANK.poiPartial` × (1 − typed / 0,7)
     (до −15): «красная» — улица Красная, а не «ТРЦ Красная Площадь»; «аэроп» — аэропорт сразу за «Аэропортовской».
   - Запрос короче 4 букв (`RANK.poiMinLetters`, без слов вида «ТЦ», «ЖК») — объекты только названные целиком: «же» не
     даёт «Учебный корпус КубГТУ» (синоним «Женская учительская семинария» → «женус»), «кра» — «Краснодарский
     политехнический институт»; «ккб» — больницы остаются.
   - Короткое начало (2–4 буквы, весь запрос): размер улицы весит больше — до +6 (`RANK.sizeShort` × доля от числа
     домов × (5 − букв) / 3), со спадом по расстоянию от `near` (4 км): «кр», «кра» — улица Красная, а не город
     «Краснодар» или «Крупской»; у точки пользователя своя «Садовая» в СНТ не уступает большой городской.
   - Одинаково на сервере и в мини-индексе браузера: признаки считаются по формам названий, которые мини-индекс
     собирает тем же кодом (27 тыс. префиксов train — 100% совпадения).
9. **Род порядкового числа**: «1-я Заречн» — «улица 1-я Заречная» (+2), «1-й Заречный проезд» — −8.
10. **Одноимённые без пункта** («Вишнёвая 5», «Карла Маркса 87»):
    - найденный дом тёзки в другом пункте выше «≈» (`approxBehindExact` = 16 × (1 − правдоподобие соседей)): если соседи той
      же чётности рядом, дом скорее есть, просто его нет в данных, и «≈» почти не опускается; «≈» в названном пункте не
      опускается;
    - близость самой точки к `near` — до +8 (спад 2 км): у точки пользователя его пункт первым;
    - `near` в посёлке, который лежит в радиусе застройки большего пункта (Яблоновский у Краснодара), — ответы в нём
      +6 (`RANK.nearHome`, `homeOf`): радиус города накрывает и посёлок, и близость пункта у них одинакова, поэтому
      «Базовская 21» у выбравшего Яблоновский раньше уходила в Краснодар (дом с точкой «≈» в Яблоновском проигрывал
      точному дому города). СНТ «своим» пунктом не считается — они мелкие и стоят вплотную;
    - главная улица пункта (втрое больше домов) подписана просто «Краснодар», микрорайон добавляется к меньшей тёзке;
    - улица без пункта в данных подписывается ближайшим пунктом, пустых подписей нет.
11. **Вид объекта** перед названием («ТЦ», «ТРЦ», «БЦ», «ЖК») — не слово названия: «Галерея» = «ТЦ Галерея».
12. **Формы объекта** (`poiForms` в `index-build.ts`): латиница кириллицей, как читают («Oz Молл» → «оз молл», «Royal
    City Mall» → «роял сити молл»), короткое название слитно («озмолл»), вид словами перед названием («аэропорт
    Краснодар - Пашковский», «вокзал Краснодар-1»), сокращения вузов и больниц («БСМП», «КГАУ», «КубГАУ»). Объект
    без пункта в данных получает пункт, в застройке которого лежит.
13. **Латинские двойники** в слове («KPACHAЯ», «HOBOPOCCИЙCKAЯ») — вариант куска кириллицей в режиме «как набрано».
14. **Номер дома латиницей** (`houseChunk` в `query.ts`): «24a», «10d», «29 k1», «24zh» — литера по начертанию (заглавные
    A B C E H K M O P T X Y, строчные a c e o p x y) или транслитом (b — б, d — д, l — л); раскладкой («a» — «ф») — только
    если так набран весь запрос. «24B», «5P», «10C», «7H» — два прочтения (24В и 24Б): оба дома — отдельные подсказки,
    строгий `geocode` при двух настоящих домах отказывается. «l20», «I20», «3OO», «1O1» — цифры (одна «O» в конце — как было: литера,
    120 — запасной ключ).
15. **Уточнения при тёзках** (строгий `geocode`), соперник не считается, если:
    - тип улицы назван явно и совпал у лучшего, а у соперника другой, и название соперника совпало не лучше
      («проезд Кропоткина, 15» при «улице Кропоткина, 15»);
    - почтовый индекс совпал у лучшего и не совпал у соперника («350912, г. Краснодар, ул. Дзержинского, 25» — в Комсомольском);
    - названный вместе с городом микрорайон — у лучшего, а соперник далеко от него («Краснодар, КМР, ул. Дзержинского, 38»).

    И наоборот, назван город, а в нём (сам город с микрорайонами и СНТ внутри) такой дом с настоящей точкой есть дважды и
    соперник объясняет запрос не хуже — отказ «уточните пункт» («г. Краснодар, улица Дзержинского, 37» — центр и
    Комсомольский; «главная улица втрое больше» больше не решает). Станица или посёлок в черте города с тем же адресом —
    не соперник: их пишут своим именем («г. Краснодар, ст-ца Елизаветинская, …»), без него адрес — в самом городе.
16. **Контекст типа**: тип перед названием действует только в том же куске (до запятой) и не после прилагательного
    («Фестивальный микрорайон Краснодар» — тип у «Фестивальный»); «мкр X» — микрорайон или улица-«микрорайон», у переулка −25,
    у пункта другого вида −12, строгий `geocode` такой ответ не берёт («мкр Музыкальный», «мкр Черноморский»); «р-н X» — регион.
17. **Слова в метке и имени объекта**: «д.»/«дом» перед номером — метка, а не буква названия («проезд Ковтюха, д. 144» — не
    «проезд им. Д. Ковтюха» с пропущенным «им.»); слова после вида объекта до запятой («ТЦ OZ Mall, …», «ЖК Лазурит, …»)
    и объекты до 1 км от найденного дома — у дома не лишние; два слова названия слитно строчными («карламаркса20») —
    разрезаются, если стоят подряд в каком-то названии; слово, которое есть в словаре целиком, до других слов — не больше
    одной правки («Вектор» — не «Нектар», «Ильинская» — не «Ильская»); дом пункта без улицы («Любимово, 8») не берётся,
    если в запросе осталось слово (номер — у названной улицы).
18. **Микрорайон — место на карте**: названный микрорайон подходит и улице соседнего пункта или СНТ, если дом не дальше
    1,5 км от него («Вектор, Земляничная 55» — СНТ рядом с микрорайоном Яблоновского), — только если микрорайон назван
    целиком, не набираемым началом слова.

Кэш совпадений слов — LRU на 20 тыс. (`lru.ts`). При наборе по буквам слова повторяются.

## Замер

Веса подбирались и качество мерялось в исходном проекте на его наборе (train / val / контрольная часть) скриптами
`scripts/geocoder-eval`, которые сюда не перенесены; история раундов и цифры — в README исходного проекта. Здесь от
них остались регрессионные тесты `tests/geocoder/*` на самодостаточных фикстурах (трудные запросы раундов 1–4 —
`hard-queries*.test.ts`).

Порядок величин оттуда же (полный индекс Краснодара, ≈ 460 тыс. домов, на inrenta не перемерялись): сборка индекса
≈ 0,4–0,5 с, `suggest` в процессе p95 ≈ 1 мс, `reverse` p95 < 0,1 мс, индекс ≈ 45 МБ кучи (+5 МБ сетка `reverse`
после первого вызова). Мини-индекс браузера совпадает с сервером на всех 27 тыс. префиксов без цифр.

## Ограничения

- Уличные запросы без номера и пункта («Садовая») неоднозначны по природе: в топ-5 попадают ближайшие к `near`.
- Обратное геокодирование — по точкам домов и улиц, без линий улиц: вдали от домов ответ — пункт.
- Старые названия улиц и ЖК — только через `aliases` и `pois` данных. Своего словаря синонимов нет, кроме
  «летия → лет» и числительных.
- Интерполяция идёт по прямой между соседями, а не вдоль линии улицы.
- В движке есть региональные константы под Краснодар и Адыгею: почтовые индексы `35…`/`36…`/`38…`
  (`queryPostcode`, `engine.ts`), сокращение «крд» → «краснодар» (`canonicalWord`), слова региона и районов
  (`REGION`, `text.ts`), шаг сетки `reverse` под широту Краснодара. Для этих данных они безвредны; для другого
  региона их нужно пересмотреть.
