# Чеклист: вход и регистрация по почте

Ручная проверка входа по почте. Автотесты (`pnpm test`) покрывают логику, здесь —
то, что они принципиально не видят: реальная БД, cookie, редиректы, письма, вёрстка.

Как всё устроено внутри — [auth.md](auth.md). Конкретные значения — сроки жизни
ссылок, льготное окно, пороги лимитов, минимальная длина пароля — там же, в
разделах «Одноразовые ссылки из писем» и «Лимиты». Здесь они намеренно не
повторяются: иначе при правке константы в коде пришлось бы помнить про два
документа.

## Подготовка

```bash
docker compose up -d db
pnpm db:migrate && pnpm db:seed     # seed раздаст владельцам пароль
pnpm dev
```

Без `SMTP_*` письма печатаются **в консоль dev-сервера** — ссылку подтверждения брать
оттуда (строка вида `[mail] to=… subject=…`).

Готовые аккаунты: `owner1@seed.local` … `owner5@seed.local`, пароль `inrenta-dev-12345`.

Полезное:

```bash
# посмотреть состояние аккаунта
docker compose exec db psql -U app -d app -c \
  "select email, password_hash is not null as has_pwd, email_verified from users order by created_at desc limit 5;"

# живые токены
docker compose exec db psql -U app -d app -c \
  "select purpose, expires_at, used_at from email_tokens order by created_at desc limit 5;"

# «протухить» ссылку, не дожидаясь суток
docker compose exec db psql -U app -d app -c \
  "update email_tokens set expires_at = now() - interval '1 minute';"
```

## 1. Регистрация

- [ ] `/login` → «Регистрация»: поля почта, имя, пароль, повтор пароля
- [ ] Пустое имя → форма не отправляется
- [ ] Пароли не совпадают → «Пароли не совпадают», запрос на сервер не уходит
- [ ] Пароль короче минимально допустимого → отказ с понятным текстом
- [ ] Успешная регистрация → экран «Письмо отправлено на …», **вход не выдан**
- [ ] Письмо в консоли: есть ссылка, указан срок её жизни (совпадает с auth.md) и
      строка «если это были не вы»
- [ ] Кнопка «Отправить письмо ещё раз» работает; **прежняя ссылка после этого мертва**
- [ ] Переход по ссылке → возврат на исходную страницу, в шапке залогинен
- [ ] Повторный клик по той же ссылке **внутри льготного окна** → снова пускает
      (антивирусы почты ходят по ссылкам раньше человека)
- [ ] Тот же клик **после льготного окна** → `/login?error=verify_token_invalid`
      с текстом. Чтобы не ждать, сдвинуть штамп:
      `update email_tokens set used_at = used_at - interval '1 hour';`

## 2. Вход

- [ ] Верный пароль → главная, сессия жива после перезагрузки страницы
- [ ] Неверный пароль → «Неверная почта или пароль»
- [ ] Несуществующая почта → **тот же самый текст** и примерно то же время ответа
- [ ] Неподтверждённый аккаунт + верный пароль → «Почта не подтверждена» + кнопка
      повторной отправки
- [ ] Неподтверждённый аккаунт + **неверный** пароль → «Неверная почта или пароль»
      (про подтверждение не говорим тому, кто пароля не знает)
- [ ] Аккаунт, заведённый через Яндекс → «У этой почты вход через Яндекс или VK»
- [ ] Забаненный юзер (`update users set banned_at = now() where email = '…'`) →
      входит, но тут же уезжает на `/banned`

## 3. Сброс пароля

- [ ] «Забыли пароль?» с зарегистрированной почтой → письмо со ссылкой; срок её
      жизни короче, чем у подтверждения
- [ ] С незарегистрированной почтой → **тот же самый ответ**, письма нет
- [ ] У аккаунта, заведённого через OAuth → тот же ответ, письма нет
- [ ] У неподтверждённого аккаунта → тот же ответ, письма нет
- [ ] `/reset?token=…` открывается, просит новый пароль дважды
- [ ] После смены — залогинен, новый пароль работает, старый нет
- [ ] **Открытая сессия в другом браузере после сброса перестаёт работать**
- [ ] Повторный переход по той же ссылке → «Ссылка недействительна» (льготного окна
      здесь нет, в отличие от подтверждения)
- [ ] `/reset?token=garbage` и без токена → объяснение, а не форма

## 3.1. Смена пароля из кабинета

Отдельный от сброса флоу: `/profile` → «Сменить пароль».

- [ ] Неверный текущий пароль → «Неверный текущий пароль», пароль не меняется
- [ ] Верный текущий + новый → пароль сменился, **текущая сессия жива**
      (страница не разлогинивает)
- [ ] Открытая сессия в другом браузере после смены перестаёт работать
- [ ] На почту приходит письмо об изменении пароля
- [ ] Аккаунт, заведённый через Яндекс или VK → «У аккаунта нет пароля»
- [ ] Новый пароль, совпадающий с почтой → отказ
- [ ] Превысить лимит попыток смены → «Слишком много попыток». Лимит считается
      **по аккаунту**, поэтому смена IP или браузера не помогает

## 4. Стоп-лист доменов

- [ ] Регистрация, ввести `a@gmail.com`, увести фокус → под полем красная строка,
      кнопка заблокирована
- [ ] Заранее, до ввода, про запрет нигде не написано
- [ ] В режиме «Войти» проверка домена не срабатывает
- [ ] Существующий аккаунт на заблокированном домене продолжает **входить** и
      **подтверждать почту** (список действует только на регистрации)
- [ ] `BLOCKED_EMAIL_DOMAINS=example.com` в `.env` + рестарт → домен закрылся
- [ ] View-source страницы `/login`: списка доменов в бандле нет

## 5. Коллизии с OAuth

- [ ] Регистрация паролем на почту существующего Яндекс-аккаунта → «уже привязана
      ко входу через Яндекс или VK», пароль у чужого аккаунта не меняется
- [ ] Вход через Яндекс на почту, где уже есть пароль → `/login` с понятным текстом,
      а не с технической ошибкой `OAuthAccountNotLinked`
- [ ] Регистрация на брошенную (неподтверждённую) регистрацию → пароль
      перезаписывается, приходит новое письмо
- [ ] Регистрация на seed-аккаунт без пароля (`ownerN@seed.local`) → аккаунт
      присваивается после подтверждения почты

## 5.1. VK-юзер без почты

VK не всегда отдаёт e-mail; тогда в `users.email` лежит заглушка
`vk-<id>@vk.placeholder`. Это ожидаемое, а не сломанное состояние — проверяем, что
оно ведёт себя предсказуемо:

- [ ] Такой юзер входит через VK как раньше
- [ ] «Забыли пароль» на его настоящую почту → нейтральный ответ, письма нет
      (аккаунта с этим адресом в базе действительно нет)
- [ ] Регистрация паролем прямо на `vk-<id>@vk.placeholder` → «уже привязана ко
      входу через Яндекс или VK», пароль чужому аккаунту не прописывается
- [ ] Регистрация паролем на его **настоящую** почту → заводится **второй,
      отдельный аккаунт**. Это осознанная цена решения «автосклейки нет»
      ([decisions/0004](decisions/0004-no-oauth-email-merging.md)): объединить их
      можно будет только через экран «Способы входа», он отложен —
      см. [BACKLOG.md](BACKLOG.md)

## 6. Модалка в точке брони

Только при `BOOKING_FLOW=auth`: при `telegram` «Забронировать» ведёт в бота, и
модалки входа в точке брони нет.

- [ ] Карточка товара → выбрать даты → «Забронировать» без входа → модалка
- [ ] В модалке есть и кнопки Яндекса с VK, и форма входа по почте
- [ ] Вход по паролю из модалки возвращает **на ту же позицию с выбранными датами**
- [ ] Регистрация из модалки: после подтверждения из письма возвращает на ту же
      позицию товара с выбранными датами

## 7. Лимиты

Пороги и окна — в [auth.md](auth.md), таблица «Лимиты». Проверяем не числа, а
поведение при их превышении.

- [ ] Превысить лимит попыток входа → «Слишком много попыток»
- [ ] Нажать «Отправить письмо ещё раз» дважды подряд, не выждав паузу → второй
      раз письмо молча не уходит, **ответ формы тот же самый**
- [ ] Превысить лимит запросов сброса на одну почту → ответ тот же, письма нет

Во всех трёх случаях важно именно то, что интерфейс не меняет ответ: иначе
форма превращается в проверялку «есть ли такой аккаунт».

Лимитер держит счётчики в памяти процесса — рестарт dev-сервера их обнуляет.

## 8. Без SMTP в проде

Проверяется на staging или `NODE_ENV=production` сборке без `SMTP_*`:

- [ ] Форма входа по паролю на месте
- [ ] «Регистрация» и «Забыли пароль?» скрыты
- [ ] Прямой вызов `register` в обход UI (из devtools) → отказ, аккаунт не создаётся

## 9. Вёрстка и темы

- [ ] Светлая и тёмная темы: поля, кнопки, красный текст ошибки читаемы в обеих
- [ ] Ширина 320 px: нет горизонтального скролла на `/login`, `/reset` и в модалке
- [ ] Автозаполнение паролей браузером срабатывает (`autoComplete` проставлен)
- [ ] Кнопки блокируются на время запроса, двойной клик не создаёт две регистрации

## 10. Прод-сборка

- [ ] `pnpm build` проходит (dev-сервер остановлен — общий `.next`)
- [ ] Docker-образ стартует и регистрация внутри него проходит: `@node-rs/argon2` —
      нативный модуль, трассировку standalone-сборки надо проверить отдельно
- [ ] Письма с боевого SMTP доходят и **не попадают в спам** (SPF и DKIM настроены)
