# Документация inrenta

Оглавление. Все документы здесь описывают **текущее состояние** проекта. Если
документ разошёлся с кодом — прав код, а документ нужно поправить в той же
задаче, где расхождение обнаружилось.

## Где ещё лежит правда

Документация объясняет смысл, но источником истины остаётся код:

| Вопрос | Источник правды |
|---|---|
| какие есть таблицы и колонки | `drizzle/schema.ts` |
| какие есть страницы и адреса | `src/app/**` |
| какие переменные окружения обязательны | `src/lib/env.ts` + `.env.example` |
| какие CSS-токены обязательны | `scripts/check-theme.ts` |
| тексты интерфейса | `theme/content.ts` |
| сколько сейчас тестов | `pnpm test` |

## Правила ведения документации

Коротко (полная формулировка — в [CLAUDE.md](../CLAUDE.md)):

1. Документация описывает то, что есть сейчас, а не то, что планируется.
2. Один факт живёт в одном месте. Если он уже есть в коде — на него ссылаются,
   а не копируют.
3. Планы реализации в репозитории не хранятся — кроме планов крупных задач,
   которые сейчас в работе: они лежат в [plans/current/](plans/current/) и
   удаляются по завершении. Значимое решение из плана переезжает в `decisions/`,
   остальное остаётся в истории git.
4. Числа, статусы и списки файлов в прозе — источник гниения. Вместо них —
   команда, которая даёт актуальный ответ.
5. Не уверен, как работает — иди в код. Не удалось установить даже по коду —
   пиши `NEEDS REVIEW` и объясняй, что именно неясно.
